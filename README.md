# orca-telegram-notifications

Плагин [Orca](https://github.com/stablyai/orca): шлёт сообщение в Telegram,
когда агент меняет статус — завершился, ждёт вашего внимания, застрял или
упал. Больше не нужно держать окно Orca перед глазами: флот агентов сам
приходит к вам в карман.

## Как работает

Воркер плагина подписан на событие `agent.status.changed`. Когда статус
агента попадает под ваш фильтр, плагин отправляет сообщение через
Telegram Bot API:

```
🤖 Orca · 14:32
Статус агента: done
Воркспейс: gt-backend/fix-auth
Панель: claude:main
```

Повторы одного статуса гасятся антидребезгом (60 секунд по умолчанию),
периодические статусы вроде `working` по умолчанию игнорируются.

## Установка

1. Settings → Plugins → включить систему плагинов.
2. Добавить источник — git URL с тегом:
   `https://github.com/NooBiToo/orca-telegram-notifications#v0.1.0`
   (или локальную папку через Development).
3. Установить, Review & enable.

## Настройка (4 шага)

1. Создайте бота у [@BotFather](https://t.me/BotFather) — получите токен.
2. Узнайте свой `chat_id` (напишите боту [@userinfobot](https://t.me/userinfobot)).
3. Скопируйте `config.example.json` → `config.json` рядом с манифестом
   и заполните:

```json
{
  "botToken": "123456789:AAAA…",
  "chatId": "123456789",
  "states": ["done", "attention", "stuck", "error", "waiting", "needs"],
  "notifyOnAll": false,
  "quietSeconds": 60,
  "silent": false,
  "dryRun": false
}
```

| Поле | Смысл |
|---|---|
| `botToken` | токен бота от @BotFather (обязательно) |
| `chatId` | id чата/канала, можно `@channelname` (обязательно) |
| `states` | ключевые слова: статус агента уходит в Telegram, если содержит хотя бы одно (без учёта регистра) |
| `notifyOnAll` | `true` — слать на любой статус |
| `quietSeconds` | пауза между повторными сообщениями об одном статусе |
| `silent` | беззвучная доставка в Telegram |
| `dryRun` | `true` — печатать сообщения в лог воркера, не отправляя |

4. Палитра команд → **Telegram: Send test message** — придёт тестовое
   сообщение. Есть и **Telegram: Send config summary**.

Событие статуса можно поймать в журнале: карточка плагина в Settings →
Plugins → лог воркера.

## Почему config.json, а не форма в панели

Панели плагинов в Orca — sandbox-iframe, которому хост разрешает только три
действия (чтение контекста воркспейса, ввод в терминал, нативные
уведомления). Ни хранилище, ни секреты, ни сеть из панели недоступны — это
осознанная модель безопасности Orca. Зато воркер — полноценный Node-процесс:
он читает `config.json` и ходит в Telegram напрямую. Токен бота при этом
лежит только у вас на диске.

## Приватность

В Telegram уходит минимум: статус, имя воркспейса, ключ панели, время.
Ни путей, ни содержимого файлов, ни промптов — payload события
`agent.status.changed` в Orca сам по себе урезан до этих полей.

## Разработка

```bash
node scripts/test-local.mjs   # 20 проверок логики без Orca и без сети
```

Локальная проверка в Orca: Settings → Plugins → Development → добавить
папку плагина → Review & enable.
